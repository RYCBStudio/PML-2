# 安装指南（26.5）

> 本文档覆盖 PML 2 的安装、更新，以及首次使用 mefrpc 客户端 / 证书助手 lego 组件的失败路径。使用问题见 [用户指南](user_guide.md)，排障见 [故障排查指南](troubleshooting.md)。

## 安装目录结构（26.5 起）

自 26.5.0 起，PML 2 采用**代码与数据分离**的版本化布局：

```
安装目录/                    ← 如 %LOCALAPPDATA%\PML 2 或 /opt/pml-2
├─ PML 2.exe                ← 启动器（版本无关，升级时唯一不被替换的部件）
├─ launcher.json            ← 版本槽位：记录当前启用的 vXXX 与回滚点
├─ v26.5.0/                 ← 代码（只读，每个大版本一个目录）
│  ├─ MEFrpLauncherX.exe
│  ├─ Tools/                ← splash 等随包分发的辅助程序
│  └─ Resources/ Assets/ *.dll runtimes/ ...
├─ legacy/                  ← 旧版残留收拢区（升级后可能出现；确认无用后可删）
└─ data/                    ← 全部可变数据（升级绝不覆盖）
   ├─ Config/                Settings.json、Render.json、device.id
   │  ├─ frp/                隧道配置文件
   │  ├─ Themes/             用户主题（selected 记录当前主题）
   │  ├─ Plugins/            插件 YAML（热重载）
   │  └─ Certificates/       ACME 证书
   ├─ Cache/                 startup.json、更新临时包、界面状态
   ├─ Logs/                  运行日志、Crash/ 崩溃日志
   └─ Run/                   运行期下载：mefrpc 客户端、lego
```

**这样设计的原因**：

- 升级只替换 `vXXX\`，`data\` 原样保留 —— 隧道、主题、插件、证书永不丢失。
- Linux 下 `data\` 可被重定向到用户目录，解决 `/opt/pml-2` 由 root 拥有、普通用户无法写入的历史问题。
- 多个版本可共存，回滚只需改 `launcher.json` 的 `current` 字段。

启动器（`PML 2.exe`）只做一件事：读取 `launcher.json`，把请求转交给当前版本的主程序，并原样透传命令行参数与退出码。快捷方式、`pml2://` 链接、脚本调用都应指向它。

## 安装

### Windows

1. 从官网/发布页下载安装程序：x64 为 `pml2_setup <版本> AOT.exe`，ARM64 为 `pml2_setup_arm64_<版本>.exe`。
2. 双击运行，按向导完成安装（默认安装到 `%LOCALAPPDATA%\PML 2`）；安装器支持静默参数：`/silent /sp- /nocancel`。
3. 安装完成后从桌面/开始菜单启动 PML 2（指向 `PML 2.exe`）。
4. 从 26.4 或更早版本升级时，首次启动会弹出**数据迁移向导**，把旧的 `Config\`、`Cache\`、`Logs\`、`bin\`、`Plugins\` 复制进 `data\`；详见下方「从旧版本升级」。

> 应用内更新**不再使用**该安装包，而是下载 `pml2-<版本>-windows-<架构>-aot.zip` 后解压，见下文「应用内更新」。

### macOS

1. 下载 `pml2-<版本>-macos-x64-aot.dmg`（Apple Silicon 为 `...-macos-arm64-aot.dmg`），双击挂载后把应用拖入「应用程序」。
2. 首次启动如提示「无法验证开发者」，在「系统设置 → 隐私与安全性」中允许打开。
3. 应用包已声明 `pml2://` URL 类型（TPCA 通用链接启动隧道），可直接从浏览器/其他应用拉起；Windows / Linux 由应用在**首次启动时自动注册**（当前用户级，无需管理员），详见 [故障排查指南「链接启动隧道」](troubleshooting.md)。

### Linux（deb）

1. 下载 `pml2-<版本>-linux-x64-aot.deb`（ARM64 为 `...-linux-arm64-aot.deb`；同时提供 `.rpm`），执行：

   ```bash
   sudo dpkg -i pml2-<版本>-linux-x64-aot.deb
   ```

2. 安装路径固定为 `/opt/pml-2`；可从应用菜单启动。

> **Linux 只读安装目录**：若 `/opt/pml-2` 对当前用户不可写，用 `PML2_DATA_ROOT` 把数据重定向到用户目录：
>
> ```bash
> PML2_DATA_ROOT="$HOME/.local/share/pml2" /opt/pml-2/'PML 2'
> ```

## 从旧版本升级（≤26.4 → 26.5+）

升级不会自动删除任何旧数据，也**不会覆盖** `data\` 中已存在的同名文件。

1. 安装新版本后首次启动，应用自动检测旧目录并弹出**数据迁移向导**，列出将迁移的每一项及其体积。
2. 点击「开始迁移」后逐项复制（**复制而非移动**，旧目录原地保留以便回滚）。
3. 迁移完成后可选择把旧目录重命名为 `*.old-<时间戳>`，确认新版本一切正常后再手动删除。
4. 重启应用使新路径生效。

若当时点了「跳过」，随时可从 **关于 → 工具箱 → 数据迁移向导** 重新执行。迁移是幂等的，重复执行不会有副作用。

| 场景 | 表现 | 处理 |
|---|---|---|
| 迁移后配置丢失 | 设置回到默认值 | 确认 `data\Config\Settings.json` 是否存在；若旧目录下有 `Config\Settings.json`，在向导中重新迁移 |
| 旧目录未被归档 | 安装目录下仍可见 `Config\` / `bin\` 等 | 归档失败（多为文件被占用）。关闭应用后手动删除或改名即可 |
| 迁移中途失败 | 向导列出「失败：…」的项 | 关闭占用该文件的程序（如 VPN/终端）后重试；已成功的项会被跳过 |
| 想回到旧版本 | —— | 旧目录仍在，把 `data\` 中对应文件拷回旧版本的 `Config\` 等位置即可 |
| 根目录有 `Resources\` / `runtimes\` / `Tools\` 等旧文件 | 新旧两套结构并存，目录看起来很“畸形” | 这是旧版扁平布局的残留，启动时会自动移入 `legacy\` 并提示删除，详见下文 |

### 旧版残留文件（`legacy\`，26.5.1 起）

安装器升级只会「新增 / 覆盖」，不会删除旧文件，因此从 ≤26.4 升级过来的安装根会同时存在新旧两套结构。
自 26.5.1 起，应用启动时会自动把**不属于当前版本**的内容收拢到安装根下的 `legacy\`：

- 旧版扁平布局的 `Resources\`、`runtimes\`、`Tools\`、`bin\`、`Config\`、`Cache\`、`Logs\`、`Plugins\`；
- 数据迁移向导归档出的 `*.old-yyyyMMdd_HHmmss\`；
- 其它任何非当前布局的残留文件。

收拢完成后会弹窗提示删除，三个选项：

| 选项 | 行为 |
|---|---|
| **立即删除** | 删除 `legacy\` 中全部内容（被占用的项会跳过并提示） |
| **打开 legacy 目录** | 在文件管理器中打开，便于自行确认后再删 |
| **稍后** | 保留不动；7 天内不再提醒，过期后会再提醒一次 |

**永远不会被搬走**（属于当前布局）：`PML 2(.exe)` 启动器、`launcher.json`、`launcher.log`、`data\`、所有 `vXXX\`、`legacy\` 自身、Inno 卸载器 `unins*.*`、系统隐藏文件（`desktop.ini` 等）。

**安全约束**：

- **只搬移、不删除** —— 删除必须由你在提示框中确认；搬走的内容不会丢失，随时可从 `legacy\` 取回。
- 文件被占用（或权限不足）时本次跳过，不阻断启动，下次启动自动重试。
- 数据迁移**尚未完成**的旧目录（`data\` 对应位置还没有任何文件）会被保护，以免稍后从「关于 → 工具箱 → 数据迁移向导」找不到源数据。

## 首次使用：mefrpc 客户端

启动第一条隧道时，应用会自动下载 mefrpc 客户端到 `data/Run/`（Windows 为 `mefrpc.exe`，Linux/macOS 为 `mefrpc.tar`），下载完成后自动解压/校验并启动隧道。

### 首次拉取失败

| 场景 | 表现 | 处理 |
|---|---|---|
| 下载失败 | 下载对话框报错/关闭，隧道未启动 | 在「设置」页切换**下载源**（TPCA ↔ 官方）后重新启动隧道 |
| 校验失败 | 提示客户端文件校验不通过 | 删除 `data/Run` 下残留的 `mefrpc*.tmp` 与损坏文件后重试 |
| 下载中断 | 下载对话框显示进度停止/取消 | 重新启动隧道即可断点重试（下载器内置 5 次重试） |

> 下载源配置 `DownloadSource`（默认 `TPCA`）同时作用于 mefrpc 客户端与应用更新包，详见 [用户指南「下载源」](user_guide.md)。

## 首次使用：证书助手 lego 组件

安装包**不内置** lego（ACME 客户端）。首次在「设置 → 隧道设置 → 证书助手」中申请证书时，会按当前平台下载对应版本（约 20 MB，校验官方 `checksums.txt` 的 SHA-256）并解压到 `data/Run/lego/<rid>/`。

| 场景 | 表现 | 处理 |
|---|---|---|
| 下载失败 | 停留在「正在准备 lego…」或提示无法准备 lego | 检查网络/代理后重试（应用会依次尝试 GitHub 主源与备用镜像） |
| 校验失败 | 同上（应用会拒绝使用未通过校验的二进制） | 重试即可；持续失败需检查网络是否被中间人代理改写 |
| 需离线或内网使用 | 无法完成下载 | 目前需能访问 GitHub 或其镜像；详见 [故障排查指南「证书申请失败」](troubleshooting.md) |

## 应用内更新

更新入口在「更新」页：检查更新 → 下载并安装。失败路径（获取失败、下载失败、校验失败、切源重试）见 [故障排查指南「更新失败」](troubleshooting.md)。

### 两类产物：安装包 vs 更新包

发布页对每个平台 / 架构 / 编译类型组合都会上传两种产物，用途**严格区分**：

| 产物 | 命名示例 | 用途 |
|---|---|---|
| **安装包** | `pml2_setup 26.5.1 AOT.exe`、`pml2-26.5.1-macos-arm64-aot.dmg`、`pml2-26.5.1-linux-x64-aot.deb`、`...-portable.tar.gz` | **仅**面向用户手动下载安装（首次安装 / 整机重装 / 修复）；应用内更新不会使用它们 |
| **更新包（zip）** | `pml2-26.5.1-windows-x64-aot.zip`、`pml2-26.5.1-linux-arm64-aot.zip`、`pml2-26.5.1-macos-x64-aot.zip` | **仅**供应用内「下载并安装」下载后解压 |

更新包文件名规则固定为 `pml2-{版本}-{平台}-{架构}-{编译类型}.zip`：

- 平台：`windows` / `linux` / `macos`
- 架构：`x64` / `arm64`
- 编译类型：`aot`（当前发布矩阵）/ `r2r`（ReadyToRun）

zip 的内容就是版本目录 `vXXX/` 的内容本身（主程序 + `Tools/` + `Resources/` + 各 DLL），**解压后直接得到 `vXXX/`**，不会多套一层父目录。

### 更新时发生了什么

更新包**不会卸载旧版、也不会原地覆盖、更不会调用系统安装器**。在分离式布局下它只做四件事：

1. 把更新 zip 下载到 `data/Cache/update_tmp_<版本>.zip`；
2. 解压到安装根下**新增的** `vXXX` 目录（`v` + 版本号，例如 `v26.5.1`）；
3. 在 `launcher.json` 里把 `current` 指向新版本，并把升级前的 `current` 记为 `previous`（回滚点）；
4. 清理其余历史 `vXXX` 目录 —— 默认**保留 `previous`**，使升级后仍可一键回滚；随后重启进入新版本。

`data\` 全程不参与覆盖，隧道、主题、插件、证书永不丢失。

> **旧版本目录的去留**：应用内更新按「设置 → 更新 → 旧版本目录」的策略决定：
>
> | 策略 | 实际行为 |
> |---|---|
> | 每次升级前询问（默认） | 升级前弹窗选择「保留（可回滚）」或「删除（省空间）」，选择会被记住 |
> | 保留旧版本 | 保留回滚点，其余可清理的历史目录一并删除 |
> | 删除旧版本 | 不保留回滚点 |
>
> Windows 下**正在运行的旧版本目录**在更新过程中无法删除（可执行文件被占用），
> 它会在新版本启动后出现在「更新页 / 工具箱」的可清理列表里。
> 无论选哪种，`data\` 都不会被触碰。

> **「仅下载 / 手动下载」模式**：这两个模式只把 zip 下载到 `data/Cache/`，
> 不会自动安装；需要时手动把 zip 解压成安装根下的新 `vXXX` 目录，并同步修改
> `launcher.json` 的 `current`。安装包（exe / dmg / deb / rpm / tar.gz）不参与此流程。

| 场景 | 表现 | 处理 |
|---|---|---|
| 升级后想回滚 | 新版本有问题 | 把 `launcher.json` 的 `current` 改回 `previous` 的目录名，重启启动器即可 |
| 解压失败 | 状态区显示「更新包解压失败…」，出现「重试下载」按钮 | 点击「重试下载」重新下载；持续失败请切换下载源（见故障排查「更新失败」） |
| 想彻底收敛磁盘 | 安装根里堆积了多个 `vXXX\` | 用「关于 → 工具箱」清理旧版本，或重新运行安装包并加 `/cleanup` |
| 应用内更新不可用 | 提示需要分离式安装布局 | 当前是 ≤26.4 的扁平布局或开发态（没有启动器与 `launcher.json`）；请从发布页手动下载安装包 |
| 卸载后重装 | 配置与隧道仍在 | `data\` 不参与卸载（`uninsneveruninstall`），重装后原样可用 |

> **安装器命令行**：`/silent /sp- /nocancel` 静默安装；`/cleanup` 升级时删除全部历史版本目录
> （含回滚点）；`/nocleanup` 显式保留回滚点（默认行为）。
> 这些参数只对**手动运行安装包**有效 —— 应用内更新已改为 zip 解压，不再传任何安装器参数。
