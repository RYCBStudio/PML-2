### 踩坑
- 当前 PAT **无创建仓库权限**（个人与组织命名空间均 403），仓库需用户网页创建后再推送。
- GitHub Actions **job 级 `if` 不能使用 `secrets` 上下文**（会整份 workflow 解析失败、0s 即失败）；
  正确写法是 job 级 `env: NUGET_API_KEY: ${{ secrets.NUGET_API_KEY }}` + step 级 `if: env.NUGET_API_KEY != ''`。

## nuget.org 改用受信发布（Trusted Publishing / OIDC）

- 用户在 nuget.org 配了受信发布策略：owner RYCBStudio，publisher GitHubActions，
  仓库 RYCBStudio/FluentAvalonia.MarkdownRenderer，workflow `publish.yml`（**文件名必须对上**）。
- 工作流改造：`publish-nuget-org` job 加 `permissions: id-token: write`，
  用 `NuGet/login@v1`（`user: RYCBStudio`）换取短期 API key，
  再 `dotnet nuget push --api-key ${{ steps.<id>.outputs.NUGET_API_KEY }}`。**仓库里无需任何 Secret**。
- 重跑方式：改 workflow 后需把 tag 重新指向新 commit 再推送（workflow_dispatch 用 tag ref 时会用 tag 上的旧 workflow 定义）。
- Release 创建步骤加了「已存在则跳过」判断，便于重复触发。
